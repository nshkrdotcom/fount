# Stage 2 implementation plan

The approved feature target is the retained original specification. This plan orders the known gaps without changing the acceptance criteria. Each task starts with a failing, observable test; full package and PostgreSQL suites follow the focused fix. Unknown semantic results remain unknown.

1. **Edit authority and candidate selection.** Validate operation targets and insertion anchors against exact selected scenes, elements, and byte spans before applying edits. Compare final scene and element order/ownership so unchanged outside-scope material cannot move. Intersect character appearances with the writer's explicit selection. Test spans, insertions, moves, selected groups, local references, overlaps, and rebases.
2. **Identity and acceptance.** Validate stored candidate/session/source/result/report lineage and review identity against the accepted head. Expand PostgreSQL rollback, FK, deferred-trigger, concurrent writer, idempotency, and stale-decision tests. Keep the original base immutable and explicit acceptance separate from generation.
3. **Probe semantics.** Implement every option currently reported as partial: adjacent extraction; behavior and reveal localization; report reuse and same-scene dependencies; changed-target continuity; measured action layout; integrated dialogue access/voice; effective profile thresholds. Test chronological/access fixtures and preserve uncertainty.
4. **Notes, retries, and recovery.** Track note dependencies across repeated partial selections and detect conflicts beyond identical targets. Persist failed inspection/repair artifacts and selectively retry unfinished work within the saved base and budget. Recover exact partial passages; copy across screenplays using new IDs and explicit cast mapping.
5. **Investigation and remaining interfaces.** Persist structured hypotheses and enforce one follow-up investigation cycle. Finish requested PDF settings, CLI error/machine-output behavior, and typed interchange negatives. Test each workflow with actual candidate pages and writer choice.
6. **Release evidence.** Run all three offline gates, Core/Workshop PostgreSQL integration, real examples where configured, and visually inspect PDFs. Record F01–F09, W01–W09, and T01–T13 as passed, partial, failed, or not run with exact artifacts. Update handoff and manifest without relabeling the original delivery report.
